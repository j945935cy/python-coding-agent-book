# 1. 聊天機器人為什麼還不是 Agent

## 本章目標

讀完本章，讀者應能分辨「一次回答」與「可觀察、可控制的行動迴圈」，並說明 Coding Agent 為什麼需要工具、狀態與停止條件。

## 從一次回答開始

聊天模型通常接收訊息，產生文字，再把文字交給使用者。這個流程適合問答，但 Coding Agent 還需要完成工作：讀檔案、修改檔案、執行測試，然後根據結果決定下一步。

因此，本書把 Agent 拆成一個明確的閉環：

```text
使用者需求 → 模型決策 → 工具呼叫 → 工具結果 → 模型再決策 → 完成或停止
```

關鍵不在於模型「看起來很聰明」，而在於每一個狀態轉換都可以被測試與中止。

## 第一個可測試切片

本書的第一個範例不連線到付費模型，而使用 `FakeModel` 預先提供兩個回應：先要求 Calculator 工具，再產生最終答案。讀者可直接執行：

```bash
uv run pytest tests/test_agent_loop.py -q
uv run python examples/v01_fake_model_loop.py
```

這個選擇刻意把「Agent 行為」與「模型供應商」分離。模型換成真正 API 前，核心迴圈已經可以用固定輸入驗證。

## 練習

1. 把範例的加法改成乘法。
2. 在測試中加入未知工具，觀察它如何變成錯誤結果。
3. 說明為什麼 `max_turns` 是安全機制，而不只是設定項目。
