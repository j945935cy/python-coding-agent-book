# 全書難度曲線審查

## 本批範圍

以 18 章初稿的正文長度、Python 程式碼區塊、練習數量、抽象程度與操作風險進行第一輪審查。這份報告評估的是目前初稿，不代表出版完成度。

## 量化摘要

- 18 章皆有「練習」與「本章驗收」。
- 原始統計中每章有 3 題練習，只有第 18 章是單一未編號任務；本批已改為基礎、進階、挑戰三層。
- 第 13、15 章原本沒有 Python 程式碼區塊；本批已補上最小 Loop 與 `asyncio.gather()` 範例。
- 第 6、7、11、14、17 章正文少於 500 個非程式碼字元，且涉及安全或抽象介面，列為下一輪優先補強。

## 建議難度分段

| 階段 | 章節 | 難度 | 讀者主要負擔 | 編輯策略 |
|---|---:|---|---|---|
| 基礎心智模型 | 1～2 | 入門 | 分辨聊天與 Agent、理解模組責任 | 以流程圖與生活化案例為主 |
| 資料與依賴 | 3～5 | 入門到初階 | dataclass、Protocol、Context、依賴注入 | 每章只引入一個 Python 抽象 |
| 工具契約 | 6～8 | 初階 | async、Registry、驗證與錯誤回傳 | 先用 Calculator，再進入通用介面 |
| Workspace 工具 | 9～12 | 初階到中階 | 路徑安全、覆寫、精確修改、Shell 風險 | 同一案例逐步加入 Read／Write／Edit／Bash |
| 控制流程 | 13～16 | 中階 | Loop、事件、平行、取消與恢復 | 使用時間軸、狀態轉換與失敗案例 |
| 整合與安全 | 17～18 | 中階 | 權限、Context 成本、Adapter 邊界 | 以完整專案驗收清單收束 |

## 已修正的難度斷點

1. 第 13 章：在完整 Loop 前加入一回合簡化程式，避免從文字演算法直接跳到正式實作。
2. 第 15 章：加入可編譯的平行工具函式，明確解釋完成順序與回傳順序不同。
3. 第 18 章：將單一練習拆成基礎、進階、挑戰，並把驗收條件改為條列。

## 下一輪優先級

1. 高：第 11 章補 Edit 失敗案例與 diff 心智模型。
2. 高：第 14 章補事件時間軸與消費端範例。
3. 高：第 17 章補權限決策表與 Context 預算範例。
4. 中：第 6～7 章增加從具體 Calculator 到通用 Registry 的過渡說明。
5. 中：為第 9～12 章建立同一 Workspace 案例，降低章間切換成本。

## 驗收

- 全書保持由低風險 Calculator 逐步走向高風險 Bash。
- 平行、取消與權限只在讀者已理解基本 Loop 後出現。
- 每章練習至少包含操作或可觀察結果，不只要求背誦名詞。
- 重要抽象章同時提供文字流程與 Python 對照。
